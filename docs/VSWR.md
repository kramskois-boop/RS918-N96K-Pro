# Защита PA по КСВ (VSWR foldback) в RS918 N96K-Pro

Документ описывает программную защиту выходного каскада по КСВ в v1.2 (патчи P0-4, P1-1…P1-3 и
этап A / A1): как она измеряет КСВ, когда срабатывает, как индицируется, как проверить и
откалибровать датчик КСВ на стенде. Защита — **только программная страховка**, а не разрешение
работать с несогласованной антенной. Общие правила — [docs/SAFETY.md](SAFETY.md) §3, сборка/прошивка —
[docs/BUILD.md](BUILD.md), состав релиза — [docs/RELEASE.md](RELEASE.md).

> **Статус:** код реализован и прошёл сборку, host-тесты и симуляцию реальных функций A1 (58/58 PASS,
> baseline 7 FAIL — ровно F2/F6). **На железе защита не испытывалась**: поведение с эквивалентом/КСВ/КЗ,
> вид `SWR!` на реальном LCD и остаточный риск F1 (ложные срабатывания на фронте TX/после dynamic tune)
> проверяются на стенде — см. §6.

## 1. Кратко

| Что | Как |
|---|---|
| Измерение | FWD/REV датчики платы → ADC2/ADC3, 5 выборок, полное измерение каждые ~50–60 мс в TX |
| Порог | `ts.vswr_protection_threshold`, меню **Configuration Menu → VSWR Protection**; **1 = OFF**, **2..10**, default **3**; EEPROM слот **426** |
| Срабатывание | VSWR (сглаженный, fast attack/slow decay) выше порога → PA bias выключается + драйв принудительно минимальный (`PA_LEVEL_0_5W`) + мигает `SWR!` |
| Удержание | Пока VSWR высокий: bias off + минимальный драйв; раз в ~0,5 с — recovery-trial (bias ON, драйв минимальный) |
| Восстановление | 10 подряд «хороших» измерений ниже (порог − 0,5) на минимальном драйве → release: bias и пользовательский уровень восстанавливаются (~1,1 с после устранения рассогласования) |
| Инвариант A1 | При активном foldback (включая trial) смена мощности любым путём не возвращает полный драйв; `ts.power_level` сохраняется и восстанавливается после release |
| Реакция | Первое защитное решение — на первом полном измерении, ~50–60 мс после начала TX (физический минимум) |

## 2. Как работает

### 2.1. Измерение мощности и КСВ

`RadioManagement_UpdatePowerAndVSWR()` вызывается в TX каждые 10 мс (`drivers/ui/ui_driver.c:7761`,
таймер `SCTimer_ENCODER_KEYS` = 10 мс). За полное измерение набирается `SWR_SAMPLES_CNT = 5` пар
АЦП (`drivers/ui/radio_management.c:55`):

* FWD — `hadc2`, REV — `hadc3`; при включённом флаге `FLAGS1_SWAP_FWDREV_SENSE` входы меняются
  (пункт меню **SWR/PWR Meter FWD/REV Swap**);
* средние значения пересчитываются в ватты `RadioManagement_PowerFromADCValue()` с учётом нуля
  датчика (`swrm.sensor_null`) и coupling-коэффициента текущего фильтра/бэнда (`swrm.coupling_calc[]`);
* КСВ считается **только если** `swrm.fwd_pwr >= SWR_MIN_CALC_POWER = 0.25 Вт`
  (`drivers/ui/ui_driver.h:142`). Иначе значение КСВ не обновляется — деления на ноль/NaN нет
  (guard P0-4, `radio_management.c:2100-2122`);
* `vswr_ratio = rev/fwd` ограничивается [0..1]; при `ratio > 0.9801` КСВ = `VSWR_MAX_CALC_VALUE = 49`
  (почти бесконечное рассогласование), иначе `(1+√ratio)/(1−√ratio)`;
* после каждого полного измерения вызывается `RadioManagement_CheckVswrProtection()` — вся логика
  защиты ниже.

Один цикл = 5 вызовов по 10 мс, поэтому **первое полное измерение и первое защитное решение**
физически возможны не раньше ~50–60 мс после начала передачи (в документации продукта — «~60 мс»).
Счётчик `vswr_settle_cnt` с `VSWR_PROTECTION_ARM_CNT = 3` (3 тика ≈ 30 мс) — это settle-окно;
реальное решение всё равно приходит на первом полном измерении.

### 2.2. Порог: меню и EEPROM

| Параметр | Значение |
|---|---|
| Меню | **Configuration Menu → VSWR Protection** (`drivers/ui/menu/ui_menu_structure.c:123`) |
| Значения | **1 = OFF** (защита выключена), **2..10** — порог в единицах КСВ |
| По умолчанию | **3** (для обновления с v1.0 поведение меняется: защита включена по умолчанию) |
| EEPROM | слот **426** (`EEPROM_VSWR_PROTECTION_THRESHOLD`, `ui_configuration.c:356-359`, `ui_configuration.h:616-619`); адреса существующих настроек не сдвинуты (P1-1) |
| Отображение | `OFF` для 1, число для 2..10 (`ui_menu.c:2625-2639`) |
| Сохранение | значение меняется сразу в RAM; в EEPROM пишется при выключении питания с сохранением настроек либо долгим нажатием F1 (метка `*` у F1 = есть несохранённые изменения) |
| Чтение | значение вне 1..10 (пустой/старый слот) → default 3 (range-check ConfigEntry + fallback P1-4) |

Примечания:

* смена порога применяется **без перезагрузки**, на следующем измерении;
* **OFF немедленно снимает уже активный foldback** (release: bias и пользовательская мощность
  возвращаются) — делать это при плохой нагрузке нельзя; OFF допустим только осознанно и на
  исправной антенне ([docs/SAFETY.md](SAFETY.md) §3);
* при активном foldback повышение порога не отпускает защиту мгновенно: release наступит только
  после 10 «хороших» измерений ниже нового (порог − 0,5) на минимальном драйве;
* загрузка дефолтов (F1+F3+F5 при включении, подтверждение BAND+ и BAND−) вернёт порог 3.

### 2.3. Состояния, гистерезис и тайминги

Константы (`drivers/ui/radio_management.c:76-85`): `VSWR_PROTECTION_HYSTERESIS = 0.5`,
`VSWR_PROTECTION_ARM_CNT = 3`, `VSWR_PROTECTION_RETRY_CNT = 8`, `VSWR_PROTECTION_RECOVERY_CNT = 10`;
сглаживание — `VSWR_DAMPENING_FACTOR = 0.25` (`ui_driver.h:145`).

Сглаженное значение `vswr_foldback_avg`: если это первое измерение или новое значение **выше**
среднего — среднее сразу равно новому (**fast attack**); иначе IIR `avg·0,75 + new·0,25` (**slow decay**).
Гистерезис применяется к этому сглаженному значению. На железе это означает: нарастание КСВ
ловится почти сразу, а «дребезг» вокруг порога гасится.

| Состояние | PA bias | Драйв | Действия |
|---|---|---|---|
| normal | по настройке | пользовательский | ждём валидного измерения; если `avg > порог` → **trip** |
| foldback (ожидание) | **OFF** (`Board_SetPaBiasValue(0)`) | **минимальный** (`PA_LEVEL_0_5W`), переустанавливается на каждом измерении | `retry++`; каждые 8 измерений (~0,5 с) → recovery-trial |
| foldback (trial) | **ON** | **минимальный** | измерение на безопасной мощности: `avg > порог` → снова mute; невалидное измерение → отмена trial; `avg` в зоне `[порог−0,5; порог]` → mute (A1, F6); `avg < порог−0,5` → `recovery++`, при 10 подряд → **release** |
| release | ON (в TX) | пользовательский | сбрасываются флаг и индикация, восстанавливается `ts.power_level`, защита снова армится |

Тайминги (при штатном темпе измерений 5×10 мс):

| Событие | Оценка |
|---|---|
| Первое защитное решение после начала TX | **~50–60 мс** |
| Интервал между recovery-trial | 8 измерений ≈ **0,4–0,5 с** |
| Подтверждение восстановления | 10 «хороших» измерений ≈ **0,5–0,6 с** |
| Полное восстановление после устранения рассогласования | **~1,1 с** (8 ожиданий + 10 подтверждений), при этом драйв всё время минимальный |
| Мигание `SWR!` | фаза меняется каждый 4-й вызов TX-метров (~40 мс) ≈ **3 Гц** |

При переходе TX→RX защита сбрасывается (`RadioManagement_VswrFoldbackReset()`, вызов в
`RadioManagement_SwitchTxRx()`, `radio_management.c:706`), поэтому **каждая новая передача начинается
с чистого состояния** и нового settle-окна.

### 2.4. Инвариант A1: смена мощности не возвращает драйв

Единственная функция, записывающая `ts.tx_power_factor` — `RadioManagement_SetBandPowerFactor()`
(`radio_management.c:1316-1330`). С этапа A в её начале стоит клэмп: если `ts.txrx_mode == TRX_MODE_TX`
и `RadioManagement_IsVswrFoldbackActive()` (возвращает `vswr_foldback_active`, TRUE также во время
recovery-trial), то применяется `PA_LEVEL_MINIMAL`, а не пользовательский уровень. `ts.power_level`
при этом **не меняется** — запрос пользователя сохраняется и применяется после release.

Поэтому пока защита активна, полный драйв не вернут ни:

* PWR-энкодер в TX и кнопка/пункт смены уровня мощности (`UiDriver_HandlePowerLevelChange`);
* меню **PA Configuration → NNm Full PWR Adjust / NNm 5W PWR Adjust** (band power adjust);
* **Tune** (Tune Power Level применяется на входе в TX, клэмп всё равно даёт минимум);
* CAT: SET-команды мощности в этой прошивке нет (0x79 только чтение), а смена бэнда в TX запрещена
  (P0-5/P1-5);
* release/выключение защиты — там драйв возвращается **штатно** (пользовательский уровень).

Это закрывает окно, когда при включённом PA bias можно было на ~50–60 мс до следующего измерения
вложить полный драйв в рассогласование (F2 из ревью S3c). Остаточное наблюдение A1-R4: пункт меню
**PA Configuration → PA Bias** может на одно измерение вернуть bias, но драйв при этом остаётся
минимальным, следующее измерение снова выключает bias — безопасно.

### 2.5. Индикация

* **`SWR!`** — мигает в боксе уровня мощности `ts.Layout->PW_IND` (там, где обычно показано
  `FULL`/`5W`/`2W`/`1W`/`0.5W`; на 480×320 и 320×240 это один и тот же бокс рядом с полем частоты
  настройки). Красный текст на синем фоне, фаза переключается каждый 4-й вызов обработчика TX-метров
  (~3 Гц); в «паузе» показывается штатный уровень мощности. На экран не выводятся причина и
  текущее значение КСВ — только факт срабатывания (`ui_driver.c:4828-4866`, P1-2).
* Индикация сбрасывается при release и при переходе TX→RX (`ui_driver.c:4746-4751`).
* **Нижняя шкала** в TX по умолчанию показывает КСВ (`ts.tx_meter_mode = METER_SWR`, init
  `uhsdr_main.c:209` и default EEPROM `ui_configuration.c:123`). Масштаб Nizar с «зумом»: КСВ < 2,0 —
  растянутый (метки 2), 2,0–3,0 — средний (метки 2/3), > 3,0 — обычный (метки 2/3/4/5); переключение
  режима нижней шкалы — `UiAction_ChangeLowerMeterUp/Down` (кнопка F2/тап по нижней шкале,
  `ui_driver.c:6297-6303`, `ui_driver.c:7479`). Отображается сглаженное значение.
* **`Pwr. Display mW`** (PA Configuration) включает числовой вывод FWD/REV мощности в мВт — нужен
  для калибровки (§5).

### 2.6. Поведение при OFF

При пороге **1** проверка выходит сразу (`radio_management.c:1927-1934`): защита не армится и не
срабатывает; если foldback уже был активен — выполняется release (bias и пользовательская мощность
возвращаются). Это осознанный диагностический режим: при плохой нагрузке OFF означает полный драйв
в рассогласование. Не оставляйте OFF «на всякий случай».

## 3. Что защита НЕ делает

* **Не защищает RX** — только передачу; в приёме КСВ не измеряется.
* **Не защищает первые ~50–60 мс передачи**: до первого полного измерения драйв пользовательский.
  Короткие CW-посылки/цифровые бурсты короче этого окна защитой не покрываются; на фронте TX
  возможны ложные или поздние срабатывания (остаточный риск **F1**, требует стенда).
* **Не работает при FWD ниже 0,25 Вт**: измерение КСВ невалидно, trip невозможен. На минимальном
  уровне 0,5 Вт защита обычно работоспособна, но при просадке питания/слабом датчике — нет.
* **Не заменяет согласование**: не настраивает антенну/тюнер, не ограничивает КСВ физически, не
  защищает внешний PA, кабель и антенну; при длительном высоком КСВ нагрев/пробой остаются риском.
* **Не выключает передачу навсегда**: recovery-trial периодически включает bias на минимальном
  драйве — это нормальная нагрузка/нагрев, но PA не «заморожен».
* **Не калибрует датчик**: на неоткалиброванном датчике возможны ложные срабатывания и неверные
  показания — отсюда default 3 и возможность поднять порог/выключить (диагностика).
* **Не гарантирует защиту при OFF** и при невалидных измерениях; не является аппаратной защитой
  (нет предохранителя/отсечки по току).
* **Не отключает питание PA**; PTT-тракт остаётся, при зависании прошивки состояние PA определяется
  железом.
* **Не влияет на RX-настройки** и не восстанавливает EEPROM; после смены прошивки проверяйте порог.

## 5. Калибровка и проверка датчика КСВ

### 5.1. Доступные меню (PA Configuration)

| Пункт меню (точное имя из кода) | Что делает | Диапазон/умолчание |
|---|---|---|
| **Pwr. Display mW** | числовой вывод FWD/REV мощности в мВт (для калибровки) | ON/OFF, по умолчанию OFF |
| **Pwr. Det. Null** | нулевой offset АЦП датчиков FWD/REV; **доступен только при включённом Pwr. Display mW**; оранжевый, если не в TX | 75..150, умолчание 100 (`SWR_CAL_MIN/MAX/DEFAULT`) |
| **SWR/PWR Meter FWD/REV Swap** | поменять местами входы FWD/REV, если метр «мёртв» в TX | ON/OFF |
| **NNm Coupling Adj.** | поправочный коэффициент мощности для бэнда (диапазоны сгруппированы: 160, 80, 40+60, 20+30, 17..10, 6, 2, 70см, 23см) | 50..150, умолчание 100 |
| **NNm Full PWR Adjust**, **NNm 5W PWR Adjust** | power-таблица драйва по бэндам (не датчик, а ВЧ-тракт) | 1..~280 (`TX_POWER_FACTOR_MIN..MAX`), умолчание — из power-таблицы |
| **Tune Power Level** | уровень мощности в TUNE (удобно для стенда) | FULL/5W/2W/1W/0.5W/as TX PWR |

Расчёт: `sensor_null` = (значение − 100)/1000 В (общий offset для FWD и REV), `coupling_calc` =
(значение − 100)/10 дБ (добавка к dBm). КСВ считается как отношение REV/FWD, поэтому coupling
влияет на абсолютные ватты и на порог валидности 0,25 Вт, а на отношение — нет.

### 5.2. Процедура на эквиваленте 50 Ом

Оборудование: эквивалент 50 Ом (≥5 Вт), внешний ваттметр/SWR-метр (желательно), стабильный БП.

1. Включить **PA Configuration → Pwr. Display mW**.
2. Подключить эквивалент 50 Ом, выбрать разрешённый диапазон (например 20 м).
3. Установить **Tune Power Level = 0.5W** (или 1W) и включить TUNE на 1–3 с.
4. Смотреть числовые FWD/REV (мВт). На идеальном эквиваленте REV должен быть близок к нулю.
   Пунктом **Pwr. Det. Null** добиться минимума REV (offset общий с FWD, поэтому после подстройки
   убедитесь, что FWD остался правдоподобным).
5. Сравнить FWD с внешним ваттметром. Пунктом **NNm Coupling Adj.** для текущего бэнда добиться
   совпадения показаний (допуск — единицы процентов/дБ, точность зависит от датчика).
6. Если FWD не реагирует, а REV реагирует — включить **SWR/PWR Meter FWD/REV Swap**.
7. Повторить п.4–6 для остальных используемых бэндов (coupling — по группам бэндов).
8. Проверить нижнюю шкалу КСВ на 50 Ом: ожидается **≈1,0–1,2**; при пороге 3 срабатываний `SWR!`
   быть не должно.

**Критерии PASS:** КСВ на 50 Ом ≈1,0–1,2; REV ≈0; FWD согласуется с внешним прибором; ложных
`SWR!` нет. **FAIL:** КСВ заметно выше 1,5 на эквиваленте, REV «гуляет», FWD не соответствует
прибору — датчик/обвязка не откалиброваны либо плата без необходимой доработки; проверьте разъёмы,
эквивалент, питание, целостность дорожек датчика; при необходимости — hardware mod (см. ниже).

### 5.3. Ограничения калибровки

* Пункт **Pwr. Det. Null** в описании меню помечен как требующий аппаратной доработки SWR-метра
  («Needs SWR meter hardware modification to work»); на немодифицированной плате диапазона
  регулировки может не хватать.
* Предупреждение `SWR Bridge resistor mod NOT completed!` (`MAX_VSWR_MOD_VALUE = 75`,
  `ui_driver.c:6219-6223`) выводится только в ветке «нет Si5351» — **не рассчитывайте на него** как
  на диагностику; проверяйте датчик калибровкой.
* На некалиброванном датчике защита может ложно срабатывать (остаточный риск F1). Разумные меры:
  откалибровать, при необходимости поднять порог (2..10), но **не выключать защиту постоянно**.
* Калибровка датчика не заменяет проверку power-таблиц (`Full PWR Adjust`) и не влияет на КСВ-ratio.

## 6. Сценарии проверки на стенде

Полный протокол приёмочных испытаний (блок VSWR, оформление результатов, доказательства) —
[docs/TESTPLAN.md](TESTPLAN.md); ниже — минимальный набор сценариев и критерии PASS/FAIL.

### 6.1. Безопасность при испытаниях

* Только эквивалент/согласованная нагрузка достаточной мощности; открытый/закороченный разъём —
  **кратковременно** и на минимальной мощности.
* Начинать с **Tune Power Level = 0.5–1 Вт**; длительность TUNE — 1–2 с, паузы между попытками.
  Внимание: по умолчанию Tune Power Level = `as TX PWR` (может быть FULL) — перед стендом
  выставьте уровень явно (`PA Configuration → Tune Power Level`).
* Не переключать нагрузку под передачей (кроме специального RF-реле в тесте V6); не касаться
  антенного разъёма при TX; следить за нагревом PA; БП с запасом по току.
* Перед испытаниями убедиться, что защита включена (порог 3), и записать исходные настройки
  (порог, coupling, sensor null), чтобы восстановить.

### 6.2. Нагрузки и ожидаемый КСВ

| Нагрузка | КСВ (теория) | Назначение |
|---|---|---|
| 50 Ом эквивалент | 1,0 | базовая проверка, отсутствие ложных срабатываний |
| 25 Ом (≥2 Вт) | 2,0 | ниже порога 3 — защита не должна срабатывать |
| 12,5 Ом (≥2 Вт) | 4,0 | выше порога 3 — защита должна сработать |
| обрыв (open) | → ∞ | срабатывание, проверка верхнего предела |
| КЗ (short) | → ∞ | срабатывание, проверка поведения |

Резисторы — безындуктивные, с запасом мощности. При 0,5–1 Вт драйва кратковременные тесты
безопасны для резисторов 2 Вт; при уровнях выше 2 Вт используйте нагрузку ≥5–10 Вт.

### 6.3. Матрица сценариев

| # | Сценарий | Шаги | Ожидаемо | PASS/FAIL |
|---|---|---|---|---|
| V0 | Базовая проверка | 50 Ом, Tune 0.5 Вт и 1 Вт | КСВ ≈1,0–1,2; `SWR!` нет; мощность штатная | PASS: КСВ в допуске и нет срабатываний |
| V1 | Ниже порога | 25 Ом (КСВ 2,0), порог 3, Tune 2 с | КСВ ≈1,8–2,4; `SWR!` нет; передача продолжается | PASS: нет foldback |
| V2 | Выше порога | 12,5 Ом (КСВ 4,0), порог 3, Tune | в течение одного полного измерения (~60 мс; с индикацией — до ~0,2 с): провал мощности, мигает `SWR!`, PA заперт (bias off + минимальный драйв) | PASS: сработало и держится |
| V3 | Обрыв | open-нагрузка, Tune 1–2 с | срабатывание как V2; КСВ-шкала в максимуме | PASS: сработало |
| V4 | КЗ | short-нагрузка, Tune 1–2 с | срабатывание как V2 | PASS: сработало |
| V5 | Сброс на новую TX | после V2: PTT off, 50 Ом, новая TX | новая передача без foldback, мощность штатная, `SWR!` нет | PASS: сброс состояния работает |
| V6 | Recovery в TX (опция) | V2 → переключить нагрузку на 50 Ом под передачей (RF-реле!) | в течение ~1,1 с (до 8 измерений ожидания + 10 подтверждающих): release, мощность восстанавливается, `SWR!` пропадает; до release драйв минимальный | PASS: release за ~1,1 с |
| V7 | Инвариант A1 | V2, затем в foldback менять мощность: PWR-энкодер, G3, **PA Configuration → NNm Full PWR Adjust**, Tune Power Level | провал мощности не растёт, полного драйва при включённом bias нет; `ts.power_level` сохраняется и применяется после release | PASS: нет бурста |
| V8 | OFF | на 50 Ом: включить порог 1, затем (опционально) 12,5 Ом кратковременно | при 1 защита не срабатывает; при смене с активного foldback — немедленный release | PASS: OFF действительно выключает |
| V9 | Энергонезависимость порога | задать порог 5, выключить питание (с сохранением), включить | **Configuration Menu → VSWR Protection** = 5 | PASS: значение сохранилось |
| V10 | Ложные срабатывания (F1) | 50 Ом, 20 передач: CW первый «dit», dynamic tune, вращение PWR, TUNE on/off, края диапазонов | `SWR!` не появляется; мощность не проваливается | PASS: ложных нет (иначе — калибровка/порог, риск F1) |
| V11 | Индикация | V2 + TX→RX | `SWR!` мигает ~3 Гц в боксе мощности, после release/RX пропадает, штатный уровень возвращается | PASS: индикация корректна |
| V12 | mW-дисплей | **Pwr. Display mW** ON на 50 Ом | FWD/REV в мВт, REV≈0 | PASS: отображение работает |

Примечания к сценариям:

* V2/V3/V4 выполнять на **минимальной мощности** (0.5–1 Вт) и коротко; foldback должен сработать
  раньше, чем PA успеет нагреться. Первые ~50–60 мс идут на пользовательском драйве — это ожидаемо;
* V6 требует безопасного RF-переключателя нагрузки; без него помечайте SKIP — логика trial/release
  проверена симуляцией A1 (58/58 PASS), но не на железе;
* V7 можно дополнить CAT-сценарием, только если есть логгер: смена бэнда в TX запрещена, SET-команды
  мощности в этой прошивке нет;
* V8 с рассогласованной нагрузкой выполняйте только кратковременно и сознательно: OFF = полный
  драйв в плохую нагрузку;
* V10 — ключевой тест остаточного риска F1: на некалиброванном датчике возможны ложные trip,
  результат фиксируйте в протоколе (какой бэнд/уровень/условие).

### 6.4. Критерии приёмки защиты

| Критерий | PASS |
|---|---|
| Срабатывание при КСВ выше порога (12,5 Ом/обрыв/КЗ) | есть, с задержкой не более одного полного измерения (~60 мс) |
| Отсутствие срабатывания при КСВ ниже порога (50 Ом, 25 Ом при пороге 3) | `SWR!` нет |
| Драйв в foldback | минимальный, не растёт при смене мощности (A1) |
| Release после восстановления нагрузки | за ~1,1 с (или новая TX — сразу) |
| OFF | защита выключена, release немедленный |
| Индикация | `SWR!` мигает в боксе мощности; сбрасывается при release/RX |
| Энергонезависимость | порог сохраняется после выключения/включения |
| Ложные срабатывания (F1) | отсутствуют на 50 Ом в серии передач; иначе — калибровка/порог |
