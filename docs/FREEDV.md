# FreeDV: opt-in сборка (B4)

Продукт по умолчанию FreeDV **не содержит**: сборка идёт с `IS_SMALL_BUILD`
(`mchf-eclipse/hardware/uhsdr_board.h:70`), как в форке Nizar, поэтому
`USE_FREEDV` не определён и FreeDV-код вырезан препроцессором. B4 добавляет
**отдельную opt-in сборку**: флаг `--freedv` у `tools/build.py` включает FreeDV,
не меняя ни одной строки поведения обычной (default) прошивки.

> ⚠️ **Сборка — только GCC 9.3.1** (см. docs/BUILD.md §1.1): прошивки, собранные GCC 15.2.1,
> на железе зависают после splash; все старые числа в этом документе относятся к GCC15-сборкам
> и помечены как история.

## Команда сборки

```
python tools/build.py all --freedv --build-dir build-freedv --force -j 8
```

Артефакты: `build-freedv/fw-mchf.bin` (+ `.elf/.hex/.map`), загрузчик
`build-freedv/bl-mchf.bin` — **не меняется**. Прошивка заливается как обычно
(через загрузчик / DFU), откат — прошивка default-сборки.

Отдельный `--build-dir` рекомендуется, чтобы default- и FreeDV-артефакты не
перетирали друг друга; `build.py` запоминает флаги и при смене конфигурации сам
делает полную пересборку.

## Что включает флаг

`--freedv` добавляет **только для прошивки** (не для загрузчика) `-DN96K_FREEDV`;
в `hardware/uhsdr_board.h` этот define включает `USE_FREEDV` **при сохранении
`IS_SMALL_BUILD`` (вариант A). Дополнительно исправлен пре-существующий
рассинхрон guard'ов, из-за которого `-DUSE_FREEDV` в small-build не собирался:

* `drivers/audio/audio_filter.c` — FreeDV FIR-состояния и их инициализация
  (были под `#ifndef IS_SMALL_BUILD`, используются под `USE_FREEDV`);
* `drivers/audio/audio_driver.c` — FreeDV IIR/FIR-инстансы, их инициализация и
  RX-фильтр (те же guard'ы);
* `drivers/audio/freedv_uhsdr.c` — `struct my_callback_state` объявлялся до
  определения (ошибка неполного типа);
* `drivers/freedv/freedv_api.c`/`freedv_api_internal.h` — в opt-in сборке не
  выделяется `struct MODEM_STATS` (10,6 КБ!) внутри `struct freedv`; для UI
  остаются только `sync`/`snr_est` (заполняются в 1600-тракте).

С включённым флагом в прошивке появляются: режим DIGI FreeDV-L/U (vkeybrd
480x320, меню `DIGITAL MODE`, маркеры спектра 875/2125 Гц), FreeDV RX/TX-тракт
(`freedv_uhsdr.c`, Codec2/FDMDV 1600), NR+FreeDV-гейты A2.

## Бюджет RAM и стека (оценка, стенд обязателен)

Бюджет сходится **только с** удалением `MODEM_STATS` (см. выше), иначе не влезает:

* heap `freedv_open(FREEDV_MODE_1600)` (аллокации при старте, ~22 блока):
  FDMDV-состояние 40 020 Б, `struct freedv` 328 Б (без MODEM_STATS), Codec2-1300
  6 344 Б + буферы 13 704 Б, NLP 1 756 Б, bpf 1 684 Б — **итого ≈ 55,4 КБ**
  (+ overhead newlib ≈ 55,6 КБ);
* static RAM **48 552 Б** (GCC 9.3.1), значит на стек остаётся ≈ **26,9 КБ**
  (131 072 − 48 552 − 55 616);
* пик стека: PendSV `UiDriver_TaskHandler_HighPrioTasks` → FreeDV RX
  (`freedv_comprx_fdmdv_1600`) ≈ **17,6 КБ** (кадр PendSV 160 Б + VLA
  `ademod_in` 1 280 Б + `fdmdv_demod` 15,3 КБ либо `codec2_decode_1300` 9,8 КБ +
  `aks_to_M2` 6,2 КБ), плюс возможное прерывание audio-ISR ≈ 1,3 КБ — **≈ 19 КБ**;
  запас ≈ 7,8 КБ. Без удаления MODEM_STATS запас был бы отрицательным (−3 КБ).
* CCM: FreeDV добавляет только FIR-состояния 496 Б (свободно 1 564 Б) — переносить
  туда что-либо ещё нельзя.

## CPU (качественно)

FreeDV 1600 = FDMDV-демодулятор (FFT 256, 16 несущих, FIR 30/960 отсчётов) +
Codec2 1300 (FFT 512 ×2, LPC-синтез) на RX; на TX — Codec2-энкодер + FDMDV-модулятор.
На 168 МГц Cortex-M4F это заметная, но исторически рабочая нагрузка (upstream UHSDR
гонял FreeDV 1600 на mcHF/F4). Ожидаемо: RX-декод в PendSV (высокий приоритет),
TX-энкод в audio-ISR. Риск — не столько «не успевает», сколько конкуренция с
96k/12k-трактом, спектром и USB; поэтому нужен замер на стенде (см. ниже).
Режимы 700C/700D в этой сборке не открываются (`freedv_open(FREEDV_MODE_1600)`).

## Ограничения/риски

* **EEPROM-совместимость.** Раскладка EEPROM не менялась, но `DigitalMode_FreeDV`
  вставлен в enum первым (индекс 1, `radio_management.h`), поэтому сохранённый
  `digital_mode` в FreeDV-сборке означает другой режим, чем в default
  (1 = FreeDV vs RTTY, 2 = RTTY vs BPSK). Значения проверяются по диапазону
  (`ui_configuration.c`), при выходе за диапазон сбрасываются в None — порчи
  EEPROM нет, но режим после перепрошивки может «смениться».
* **NR во время FreeDV не работает** (осознанно: общий union `mmb`, гейты A2);
  в аналоговых режимах NR доступен как обычно.
* **320x240 vkeybrd**: у `Keypad_ModSel320x240` `NumberOfKeys = 10` в обеих
  конфигурациях (наследие upstream), поэтому два FreeDV-ключа не помещаются в
  сетку 2×5; выбирать FreeDV на 320x240 нужно через меню `DIGITAL MODE`.
  На 480x320 всё помещается (15 ключей).
* **Патч vendor-кода** (`MODEM_STATS`) действует только под `N96K_FREEDV`;
  default-сборка на GCC 9.3.1 — 312 216 / 42 392 / 63 476, 50 предупреждений (all),
  host-тесты — PASS (исторические GCC15-цифры 321 392/42 616/63 476 невалидны).
* Runtime на железе не проверялся (железа нет). Это сборка «для стенда».

## План стенда

1. Залить `build-freedv/fw-mchf.bin` (bootloader не трогать), проверить старт,
   версию, отсутствие hard fault.
2. Включить DIGI → FreeDV; проверить появление ключей FreeDV-L/U (480x320) и
   пункта FreeDV в меню `DIGITAL MODE` (320x240 — только меню).
3. RX: подать эталонный FreeDV 1600 сигнал (запись/WebSDR/второй трансивер с
   FreeDV) — должны появиться SNR/BER, звук; проверить захват синхронизации и
   отсутствие самопроизвольных рестартов.
4. TX: включить передачу (эквивалент/антенна), принять сигнал компьютером с
   FreeDV-модемом или вторым RS918 — проверить декодирование текста/речи.
5. Контроль бюджета: следить за `FreeDVTXUnderrun`-событиями (profiling),
   подвисаниями водопада/меню; при сбоях — снять stack/heap-«канарейку»
   (`Canary_Create()` вызывается сразу после `FreeDV_mcHF_init()`,
   `src/uhsdr_main.c`).
6. CPU: сравнить плавность спектра/водопада и задержку меню в FreeDV и SSB;
   при возможности — toggle-GPIO/осциллограф вокруг `freedv_comprx`/`freedv_comptx`
   (в коде есть закомментированные `profileTimedEventStart/Stop`).
7. Проверить переключения: SSB ↔ FreeDV ↔ RTTY/BPSK, выход из DIGI (NR должен
   стартовать с чистых буферов), смену диапазонов/частоты.
8. Проверить перепрошивку обратно на default-сборку: режимы и настройки не
   теряются (см. ограничение по индексам digital_mode).

## Возврат к обычной сборке

```
python tools/build.py all --build-dir build --force -j 8
```
или просто собирать без `--freedv`. Default-конфигурация (GCC 9.3.1) — 312 216 / 42 392 / 63 476,
50 предупреждений (all; firmware-only 46); исторические GCC15 A/B-цифры (321 392 / 42 616 / 63 476)
невалидны для железа.
