**Версия:** `2.9.48-n96kp3` (`fwv-2.9.48-n96kp3`), загрузчик **5.0.4**.

**Назначение:** проверить «что получилось» на реальном железе после прошивки собранного v1.2: идентификацию, RX/TX, защиту по КСВ (главный блок этапа A), CAT/USB-аудио, устойчивость; собрать доказательства и, при необходимости, выполнить откат.
**Статус документа:** рабочий протокол этапа B2. Все названия меню, экранов, значения и адреса ниже сверены по коду `mchf-eclipse/` и по артефактам `release/v1.2/`; ничего в коде не менялось.

## 0. Как пользоваться протоколом

### 0.1. Формат тестов и статусов

Каждый тест имеет ID вида `БЛОК-NN` (например `VSWR-04`). Для каждого теста в отчёте заполняется строка:

| Поле | Что писать |
|---|---|
| ID | `VSWR-04` |
| Условия | нагрузка, порог, мощность, режим, длительность |
| Ожидание | критерий из протокола (число/наблюдение) |
| Факт | что реально произошло (числа: Вт, КСВ, мс, с; для видео — таймкод) |
| Статус | `PASS` / `FAIL` / `NA` (неприменимо, с причиной) / `PARTIAL` |
| Доказательство | имя файла фото/видео/лога из папки испытаний (§10.1) |

**Правила:**

* `PASS` — ожидание выполнено полностью и повторяемо (для критичных тестов — не менее 2–3 повторов).
* `FAIL` — ожидание не выполнено, есть отклонение в цифрах/поведении либо небезопасное поведение.
* `NA` — тест неприменим к данному экземпляру/оснастке; причина обязательна.
* Любое **непреднамеренное полномощное излучение в рассогласованную нагрузку**, отсутствие `SWR!` при КСВ выше порога, TX без нагрузки или зависание, требующее передёргивания питания **во время передачи**, — это `FAIL` всего прогона независимо от остальных результатов (см. §9.3).
* Тесты с пометкой **must-pass** обязательны для приёмки; остальные — nice-to-have.

### 0.2. Порядок выполнения (рекомендуемый)

1. **§1 Артефакты** (за столом, без железа) → 2. **§2 Подготовка/бэкап** → 3. **§3 Прошивка и идентификация** → 4. **§4 RX** → 5. **§5 TX на 50 Ом, малые мощности** → 6. **§6 VSWR-защита** (только после успешного §5) → 7. **§7 CAT/USB-аудио** → 8. **§8 Регрессия/устойчивость** → 9. **§9 Приёмка** → 10. **§10 Доказательства/откат**.

Ориентировочная длительность: 4–6 часов чистого времени (плюс паузы на охлаждение PA). Испытания VSWR выполнять **после** проверки TX на 50 Ом и калибровки индикации FWD/REV (или хотя бы контроля внешним КСВ-метром).

### 0.3. Источник истины и известные расхождения в документации

Приоритет: **код `mchf-eclipse/` → артефакты `release/v1.2/` → docs**. В ходе подготовки протокола выявлено два расхождения, которые нужно учесть (и передать в правку документации):

1. **docs/BUILD.md §5.1** описывает обновление прошивки как «на ПК появляется съёмный диск». По коду загрузчик работает как **USB-хост**: он монтирует USB-накопитель, вставленный в трансивер (`bootloader_main.c:30-39` — «USB Host logical drive path», `f_mount` в `bootloader_main.c:144`, драйвер `usbh_diskio.c` в `f4-bootloader.mak`). Порядок в §3.2 дан по коду.
2. **release/v1.2/RELEASE-NOTES.md** говорит «включить трансивер → автообновление». По коду без удержания **BAND−** при включении загрузчик уходит в прошивку (`bootloader_main.c:339-359`), обновления не будет. В §3.2 — процедура по коду.

### 0.4. Безопасность (обязательный минимум)

* Передача — **только** в эквивалент 50 Ом ≥5 Вт (лучше 10 Вт). Для сценариев с КСВ допускаются только малые мощности (0,5–2 Вт) и короткие включения; см. §6.1.
* Не передавать без нагрузки/эквивалента; не касаться антенного разъёма при передаче; не оставлять PA включённым надолго.
* Питание — стабильный БП 13,8 В с запасом по току; не прошивать/не выключать питание во время записи flash.
* Не вскрывать корпус под напряжением, не трогать плату без ESD-защиты.
* Передавать только в разрешённых любительских диапазонах и в пределах своей лицензии. Программный запрет TX вне бэндов (P0-5) — страховка, а не разрешение.
* Защита по КСВ — программная страховка, **не** разрешение работать с неисправной антенной; при активной защите смена мощности не возвращает драйв (A1) — на это можно опираться, но тестировать защиту нужно осознанно.
* При любом подозрении на перегрев/запах/нештатный звук — немедленно прекратить передачу и снять питание.

### 0.5. Что этим протоколом НЕ проверяется

* FreeDV (в сборке **выключен**: `IS_SMALL_BUILD`, `USE_FREEDV` не определён; в прошивке нет FreeDV-функций — это не дефект, см. `docs/PATCHES.md` P2-2/A2).
* Платформы OVI40/OVI40-H7 (продукт только F4/mcHF).
* Точные метрологические параметры (чувствительность, IMD, подавление зеркала) — только качественная оценка «на слух»/по индикаторам; для лабораторных измерений нужен отдельный стенд.
* Работа с реальной антенной, полевые условия, ЭМС с другими передатчиками.

### 1.3. Проверка версий внутри `.bin` (must-pass)

Строки версий в бинарниках проверяются **побайтово** (ASCII). `findstr` по бинарнику **не работает** (проверено: не находит), поэтому используйте PowerShell:

```powershell
cd "E:\harnet\sdr 11\RS918_Nizar96K_Pro\release\v1.2"
function Test-BinString([string]$path,[string]$s) {
  $txt = [System.Text.Encoding]::ASCII.GetString([System.IO.File]::ReadAllBytes($path))
  $i = $txt.IndexOf($s)
  if ($i -lt 0) { "ABSENT : $s" }
  else { "FOUND  : '{0}' @ offset {1} (0x{1:X})" -f $s, $i }
}
Test-BinString .\fw-mchf.bin                'fwv-2.9.48-n96kp3'
Test-BinString .\fw-mchf.bin                'VSWR Protection'
Test-BinString .\fw-mchf.bin                'Tune Power Level'
Test-BinString .\bl-mchf-5.0.4.bin          'Version: 5.0.4'
Test-BinString .\bl-mchf-5.0.4.bin          'Version: 4.1.2'
Test-BinString .\bl-mchf-4.1.2-known-good.bin 'Version: 4.1.2'
```

### 2.4. Резервная копия прошивки (must-pass)

**Вариант 1 (без программатора; через загрузчик)** — безопасный дамп без обновления:

1. Подготовить **пустой** FAT32-накопитель (без `fw-mchf.bin`!) — можно с любыми другими файлами, но без `.bin` в корне.
2. Выключить трансивер, накопитель пока не вставлять.
3. Зажать **BAND−**, включить питание; после появления экрана загрузчика **отпустить BAND−** (важно: отпустить до того, как загрузчик увидит накопитель, иначе он попытается обновляться и при отсутствии `fw-mchf.bin` уйдёт в ошибку `Error Code 2`).
4. Вставить накопитель в USB-разъём (host) трансивера.
5. Дождаться строк `Saving Flash to "fw-mchf.old"...` и затем `Skipping firmware update.`, `Finished.` — на накопителе появится `fw-mchf.old`.
6. Скопировать `fw-mchf.old` в папку испытаний; зафиксировать размер — **983 040 Б** (960 КиБ: приложение 0x08010000..0x080FFFFF; `command.c:177-226`, `flash_if.h:46,58` → `MCHF_FLASHRESERVED=64` КиБ). Это бэкап **только прошивки**, без загрузчика и конфигурации.

**Вариант 2 (полный бэкап 1 МиБ; если есть ST-Link/SWD)**:

Снять дамп всех 1 МиБ flash (загрузчик 0x08000000..0x08007FFF, конфиг-эмуляция 0x08008000..0x0800FFFF, прошивка 0x08010000..0x080FFFFF; сохранить SHA-256):

```
STM32_Programmer_CLI.exe -c port=SWD -r 0x08000000 0x080FFFFF "backup-full-1MiB.bin" -rst
```

(альтернатива: OpenOCD `dump_image backup-full-1MiB.bin 0x08000000 0x100000`.) Если SWD нет — вариант 1 обязателен, полный дамп — nice-to-have.

**Вариант 3 (если прошивка уже не стартует)** — ROM-DFU: BAND+ при включении (§3.3), оттуда можно прошить загрузчик/прошивку.

### 2.5. Подготовка USB-накопителя для обновления

* Файловая система **FAT или FAT32**, один раздел, **не exFAT/NTFS** (требование загрузчика: FatFs).
* Свободно ≥2 МБ (дамп `fw-mchf.old` ~960 КиБ + при необходимости файл прошивки 314 КиБ).
* В **корне** — ровно `fw-mchf.bin` (321 392 Б; SHA из §1.2). Больше никаких `.bin` в корне.
* Отключить на ПК индексацию/автосинхронизацию съёмного диска, безопасно извлекать.

## 3. Прошивка и идентификация (блоки FLASH, BOOT, ID)

### 3.1. Два способа прошивки — что выбрать

| Способ | Что можно шить | Что нужно | Когда применять |
|---|---|---|---|
| **A. USB-накопитель через загрузчик** | Только прошивку (`fw-mchf.bin`) | USB-накопитель FAT/FAT32; **USB-host** разъём трансивера (на mcHF — «большой» USB-A; на конкретном RS918 проверяется по факту появления `USB Drive detected.`) | Основной штатный способ обновления прошивки |
| **B. DFU (STM32 ROM bootloader)** | Прошивку (`fw-mchf.hex`), загрузчик (`bl-mchf-5.0.4.hex`/`.bin`) | USB-кабель к ПК, STM32CubeProgrammer/dfu-util; вход: **BAND+** при включении | Загрузчик (только так); прошивка — если способ A недоступен/не работает |

Загрузчик **не обновляет сам себя** через USB-накопитель (в коде ищется ровно `fw-mchf.bin`: `command.h:51-56`). Загрузчик/BOOT-5.0.4 — только DFU/SWD.

### 3.2. Способ A: прошивка через USB-накопитель (по коду загрузчика)

**Подготовка:** накопитель из §2.5 (FAT32, `fw-mchf.bin` 321 392 Б в корне, SHA из §1.2); трансивер выключен; антенна заменена эквивалентом 50 Ом; БП стабилен; питание не прерывать.

1. Вставить USB-накопитель в USB-разъём трансивера.
2. Зажать **BAND−** и включить питание (PWR). После появления экрана PWR отпустить, BAND− **держать**.
3. На экране — экран загрузчика: `mcHF QRP Bootloader`, `Firmware Name: fw-mchf`, `USB Drive Mode`, `Release Band- to skip firmware update`.
4. Дождаться `USB Drive detected.` → `Firmware will be updated...` → `Saving Flash to "fw-mchf.old"...` (сохранение старой прошивки на накопитель; ~960 КиБ, до 1–2 мин в зависимости от накопителя).
5. После появления `Updating firmware using "fw-mchf.bin"...` кнопку **BAND−** можно отпустить.
6. Дождаться `Finished.` и `Remove drive or press Band- to reboot.` / `Press Power to switch off.` **Не выключать питание** до `Finished.`.
7. Извлечь накопитель (или нажать BAND− для перезагрузки) → трансивер стартует с новой прошивкой. Убедиться в наличии `fw-mchf.old` на накопителе, сохранить его в папку испытаний (§10.1) как бэкап предыдущей прошивки.

**Только дамп (без обновления):** включить загрузчик с зажатым BAND−, дождаться экрана и **отпустить BAND− до вставки накопителя**; затем вставить накопитель без `fw-mchf.bin` в корне и дождаться `Saving Flash...` → `Skipping firmware update.` → `Finished.`. Признак `was_download` фиксируется в момент обнаружения накопителя (`bootloader_main.c:151-172`): если BAND− уже отпущена — обновление пропускается; если нажата, а файла нет — будет `Error Code 2`.

**Ошибки:** при сбое на экране `Error Code N` + текст (`Error Code 1` — USB problem, `2` — `fw-mchf.bin` not found, `5` — проблема чтения файла, `6/7` — flash program/erase, `8` — write protected; `command.c:57-68`), красный LED мигает сериями. Действия: выключить питание, проверить FAT32/имя файла/размер и SHA, повторить. Расшифровка LED-кодов и восстановление — [docs/BOOTLOADER.md](BOOTLOADER.md).

**Признак успеха:** после перезагрузки System Info → `Firmware = 2.9.48-n96kp3`, `Build = Nov 26 2026 - 23:58:46` (для релизного бина), `Bootloader = 5.0.4`.

> **Замечание к документации.** docs/BUILD.md §5.1 описывает «на ПК появляется съёмный диск» — по коду это не так (см. §0.3): загрузчик — USB-хост и читает накопитель, вставленный в трансивер. Если на вашем экземпляре RS918 нет USB-host разъёма и способ A невозможен — используйте способ B (DFU, §3.3) и зафиксируйте это в отчёте.

### 3.3. Способ B: DFU (STM32 ROM bootloader) — прошивка и загрузчик

**Вход в DFU:** выключить; зажать **BAND+**; включить питание; на экране — `DFU Update Mode`, `Keep Power pressed until finish.`, `Release Band+ to start DFU Mode.`, `Screen may go white. This is ok.`, `PC should recognize new USB device.`. Отпустить BAND+ (кнопку питания, как требует экран, удерживать до конца операции) — загрузчик переходит в системный DFU STM32 (`BOOT_DFU`, `bootloader_main.c:332-338`, `400-428`); экран может стать белым — это нормально.

**На ПК** появится устройство DFU STM («STM32 BOOTLOADER»/«STM Device in DFU Mode», производитель STMicroelectronics).

* **Прошивка (fw):** `STM32_Programmer_CLI.exe -c port=USB1 -w fw-mchf.hex -v -rst` — адрес 0x08010000 берётся из hex. Для DFU с DfuSe нужен `.dfu` (в релизе его нет) — используйте CubeProgrammer с `.hex`, либо способ A.
* **Загрузчик (bl):** `STM32_Programmer_CLI.exe -c port=USB1 -w bl-mchf-5.0.4.bin 0x08000000 -v -rst` (или `.hex`). **Не включать полное стирание чипа** (full chip erase) — иначе будут стёрты секторы эмуляции конфигурации 0x08008000..0x0800FFFF и бэкап настроек. Не отключать питание во время записи загрузчика.

**Выход:** после `-rst`/перезагрузки — обычный старт; проверить System Info.

### 3.4. Первый старт после прошивки

1. Включить (PWR), дождаться главного экрана; проверить отсутствие «мигающего» экрана/циклической перезагрузки.
2. System Info: `Firmware`, `Build`, `Bootloader`, `RF Board`, `Audio Codec Presence`, `Touchscreen`, `Flash Size (kB)`, `EEPROM`, `CPU` — записать (ID-таблица).
3. Настройки: v1.2 **не добавляет** новых EEPROM-слотов (последние добавлены в v1.1: 426 VSWR, 430 CW-флаги, 524 AGC; v1.2 — только код/доккоммиты), поэтому при обновлении v1.1→v1.2 настройки должны сохраниться. При обновлении с v1.0/сторонних сборок возможен сброс/неверное чтение (раскладка расширена) — зафиксировать, при необходимости `Restore Config` или ручная перенастройка.
4. Если после прошивки «пропали» настройки — это известное следствие смены раскладки EEPROM, не дефект v1.2; записать в отчёт.

## 4. Приём (RX) — блок RX

Общие условия: антенна заменена генератором/эквивалентом с сигналом (или подключена комнатная антенна для оценки эфира), наушники, уровень громкости комфортный. Для измерений удобен генератор CW/SSB; допустима качественная оценка «на слух» + спектр/водопад.

### 4.1. Панорама/спектр 96 кГц, zoom, waterfall (must-pass)

По коду: спектр 256/512 точек, при `Spectrum Magnify = 1x` — полоса **96 кГц** (375 Гц/бин), при `8x` — **12 кГц** (46,9 Гц/бин) (`ui_spectrum.c:254-255`; `ui_menu.c:2222-2245`; FFT 256 в `ui_driver.c:6272-6274`).

Шаги:

1. `Display Menu` → `Spectrum Type` = `DUAL` (или `WFALL`/`SCOPE`), `Spectrum Magnify` = `1x`.
2. Подать на вход два сигнала с разностью ~30 кГц (или использовать две станции): оба должны быть видны **одновременно** на панораме — подтверждение полосы ~96 кГц (±48 кГц от центра).
3. Переключить `Spectrum Magnify` = `8x` (или touch-zoom): полоса сужается до ~12 кГц, детализация растёт; частота настройки не «уезжает».
4. Проверить водопад: `Display Menu` → `Wfall Speed`, `Wfall Contrast`, `Wfall Colours`; движение водопада плавное, без остановок/разрывов.
5. Переключить `Spectrum Type` = `SCOPE`/`OFF` и обратно — без зависаний и артефактов.

Критерии: полоса 1x ≈ 96 кГц (два сигнала 30 кГц apart видны одновременно); 8x ≈ 12 кГц; переключения без зависаний; водопад/спектр обновляются.

### 4.2. Перестройка, бэнды, шаги

* Вращение главного энкодера — плавное, без «перескоков»; `STEP+/-` меняет шаг; `BAND+/-` переключает бэнды (80/40/20/10 м проверить); реле LPF слышны, но без «залипаний» и потери приёма.
* RIT/XIT (если используется) — проверить отображение и возврат.
* Dynamic Tune Steps: меню `Configuration Menu` → `Dynamic Tune Steps` — при быстром вращении шаг растёт (nice-to-have).

### 4.3. Шумопонижение NR (must-pass для базовой работы)

* `G2` (коротко) циклически переключает DSP-режимы: `OFF → NR → AUTO NOTCH → NR+NOTCH → MANUAL NOTCH → PEAK` (`audio_driver.h:519-527`); текущий режим виден в индикаторе энкодера.
* Включить NR: шум/шипение заметно снижаются, речь разборчива, без «металлического»/«водяного» призвука; `DSP Functions Menu` → `DNR Threshold` меняет агрессивность.
* Выключить NR — звук возвращается без щелчка/тишины.
* **A2-проверка (обязательно):** переключиться в DIGI-режим (например RTTY/BPSK; при необходимости `Standard Menu` → `Enable DigiModes`), затем вернуться в USB/LSB; включить NR — приём должен работать, без «мёртвой тишины»/NaN (`AudioNr_Prepare()` сбрасывает NR при выходе из DIGI, `audio_driver.c:1511-1522`).
* NB: `M2` (энкодер 2 режим)/меню `RX Noise-Blanker Level` — включить/выключить, проверить отсутствие влияния на полезный сигнал (nice-to-have).

### 4.4. Фильтры 300 Гц … 2.9 кГц (must-pass)

* Доступные полосы: `100Hz, 150Hz, 300Hz, 500Hz, 600Hz, 1.4k, 1.6k, 1.8k, 2.1k, 2.3k, 2.5k, 2.6k, 2.7k, 2.75k, 2.8k, 2.9k, 3.2k…10.0k` (`audio_filter.c:46-85`).
* Настроить в `RX Filter & Equaliz`: `CW Filter 1..4` — например 300 Гц / 500 Гц / 600 Гц / 1.4k; `SSB Filter 1..4` — например 1.8k / 2.3k / 2.6k / **2.9k**.
* `G4` (коротко) переключает 4 фильтра текущего режима; в CW — проверить 300 Гц (узко, «телеграфно»), в SSB — 2.9k (широко); индикатор полосы на экране меняется.
* Убедиться, что при смене фильтра нет провалов/«бульканья», уровень не скачет катастрофически; вернуться к среднему фильтру.

### 4.5. Режимы USB/LSB/CW/AM/FM (must-pass)

* `G1` (коротко) — следующий режим; `G1` длинно — альтернативный (USB↔LSB, AM↔SAM, CW-боковая, FM девиация).
* Проверить приём в USB и LSB (разные боковые), CW (тон/фильтр/offset), AM (звук, AGC), FM (шум/девиация, при наличии станции).
* Переключения без щелчков высокого уровня, зависаний, «залипания» тишины.

### 4.6. Эквалайзер, notch, peak

* `RX Filter & Equaliz` → `SSB RX EQ Bass/Treble` (частота/усиление/ширина) — на слух тембр меняется (nice-to-have).
* `G2` до `MANUAL NOTCH`: `ENC2` (автоматически в режиме `NOTCH_F`, `ui_driver.c:6365-6368`) настраивает частоту режекции; подать несущую/гетеродин и убедиться, что тон подавляется, остальной спектр сохраняется.
* `G2` до `PEAK`: аналогично `PEAK_F` — узкий пик-фильтр подчёркивает CW-тон.
* Вернуть DSP в `OFF` после проверки.

### 4.7. S-метр и индикаторы (must-pass базово)

* S-метр реагирует на сигнал (S1…S9+), при перегрузке АЦП краснеет первый сегмент (clip) — это норма.
* `Display Menu` → `Smeter calibrate` — сдвигает показания; убедиться, что регулировка работает.
* **Числовой dBm-индикатор в этой сборке принудительно выключен** (NIZZZ: `EEPROM_DISPLAY_DBM` диапазон 0..0, `ui_configuration.c:189`; `ui_spectrum.c:2441`); его отсутствие — **не FAIL**, а известное ограничение. S-метр показывает S-единицы.
* Нижний индикатор: `F2` длинно переключает режим SWR/ALC/AUD (`UiAction_ChangeLowerMeterUp`; отображение используется в TX, см. §5); проверить переключение без артефактов.

### 4.8. Сохранение настроек в EEPROM (must-pass)

1. Изменить несколько параметров: частоту/бэнд, фильтр, уровень мощности (G3), `VSWR Protection` = 5, `Smeter calibrate` = +2.
2. Выключить штатно: **длинное нажатие PWR** (только в RX) → экран `Powering off...`, затем `Saving settings to I2C EEPROM` (или `Saving settings to Flash Memory` — зависит от того, где хранится конфигурация, `ui_driver.c:5025-5030`) / `Saving settings finished` (`ui_driver.c:5018-5050`, `7300-7313`).
3. Включить — значения восстановились (включая `VSWR Protection = 5`; после теста вернуть 3).
4. Проверить «выключение без сохранения»: зажать **BAND+** и длинно нажать PWR → `...without saving settings...` (`ui_driver.c:7294-7297`); последние изменения не сохраняются (nice-to-have).
5. Длинное нажатие **F1** — «сохранить настройки» без выключения (индикация `Saving settings...`; `ui_driver.c:6690-6716`).

### 4.9. Общее качество приёма, AGC, регрессия RX

* AGC: `AGC (RX) Settings` — переключение пресетов/параметров; на сильном сигнале нет «затыкания», на слабом — шум не «взлетает» (nice-to-have).
* 10–15 минут непрерывного приёма с включённым спектром/водопадом: без зависаний, перезагрузок, пропаданий звука.
* Переключение зумов/режимов/фильтров подряд 20–30 раз — без клина UI.

### 4.10. Тесты RX

## 5. Передача (TX) — блок TX

> **До начала §5:** эквивалент 50 Ом ≥5 Вт подключён, внешний ваттметр включён, питание стабильно. Первые передачи — **0,5 Вт**, длительность 2–3 с. Все тесты §5, кроме отдельно оговорённых, — только в эквивалент.

**Тракт:** RX 96 кГц / TX 12 кГц с целочисленной децимацией/интерполяцией (кодек I2S 96 кГц: `uhsdr_main.c:110`; внутренняя ЦОС 48 кГц: `audio_driver.h:29`; TX-децимация 4:1 — `RX_DECIMATION_RATE_12KHZ = 4`, `audio_driver.h:491`; см. README, раздел «Аппаратная цель»).

### 5.1. Уровни мощности (must-pass)

* Уровни: `FULL`, `5W`, `2W`, `1W`, `0.5W` (enum `PA_LEVEL_*`, `hardware/uhsdr_board.h:498-506`); индикация в боксе PWR — `FULL/5W/2W/1W/0.5W` (`ui_driver.c:4722-4737`); смена — `G3` (коротко, +1 по кругу), `ui_driver.c:6544-6550`; default после сброса — **2W** (`PA_LEVEL_DEFAULT`).
* Поочерёдно выставить 0.5/1/2/5/FULL, передать 2–3 с (SSB, микрофон) и записать показания внешнего ваттметра. Ожидание: **монотонный рост** мощности, метки совпадают с уровнем; FULL — максимальная мощность (записать фактическую, Вт).
* Проверить, что PWR-индикатор соответствует выбранному уровню.

### 5.2. Tune Power и восстановление уровня после Tune (must-pass; P2-4/#1750)

Меню `PA Configuration` → `Tune Power Level`: варианты `as TX PWR`, `0.5W`, `1W`, `2W`, `5W`, `FULL POWER` (`ui_menu.c:3957-3972`).

1. Установить пользовательский уровень, например `2W` (G3), и `Tune Power Level = 1W`.
2. Нажать **F5 (`TUNE`)** — включается несущая; внешний ваттметр ≈ **1 Вт**; бокс PWR показывает уровень Tune.
3. Нажать F5 снова — выход из Tune; **PWR-индикатор и фактическая мощность возвращаются к пользовательскому уровню 2 Вт** (это и есть проверка восстановления; `radio_management.c:215-263`).
4. Повторить с `Tune Power Level = as TX PWR` — в Tune мощность равна пользовательской; и с `FULL POWER` — в Tune полная.
5. Проверить, что после Tune следующий обычный TX (PTT) идёт на пользовательском уровне, а не на Tune-уровне (известный upstream-дефект #1750, закрыт в P2-4).

### 5.3. ALC, компрессор, эквалайзер (must-pass базово)

* `Compressor & Inputs` → `Enable TX Compressor -->` (вкл/CUSTOM параметры: `Compressor Input Gain`, `Compressor Ouput Gain`), `TX Input Select` = MIC.
* Нижний индикатор: `F2` длинно → `ALC`; при разговоре стрелка ALC отклоняется, не «прилипает» к максимуму, при молчании — на нуле (`ui_driver.c:4986-4992`).
* `TX Filter & Equaliz` → `SSB TX Voice Equaliz` + `Bass/Treble` — на слух (монитор/второй приёмник) тембр меняется; без возбуждения/искажений.
* AUD-метр (`F2` длинно → `AUD`) — отклоняется при речи, сбрасывается.

### 5.4. CW: ключ, paddle, sidetone, скорость (must-pass)

* `CW Mode Settings`: `CW Keyer Mode` (`IAM A`, `IAM B`, `STR_K`, `ULTIM`), `CW Keyer Speed` (WpM), `CW Keyer Weight`, `CW Sidetone Gain`, `CW Side/Offset Freq`, `CW Paddle Reverse`, `CW TX->RX Delay` (`ui_menu_structure.c:397-421`).
* Подключить ключ/paddle: передать точки-тире; **sidetone слышен в наушниках**, скорость соответствует WpM; `Paddle Reverse` меняет dit/dah; в эквиваленте — ВЧ-мощность (CW), контроль внешним ваттметром.
* Проверить задержку возврата в RX (`CW TX->RX Delay`).
* Нажать/отпустить ключ — нет залипания передачи (после отпускания через заданную задержку возврат в RX).

### 5.5. PTT-пути (must-pass)

* Микрофонный PTT: TX/RX по нажатию/отпусканию.
* CAT PTT — проверяется в §7 (rigctl/WSJT-X).
* `F5` — Tune (несущая), выход по повторному нажатию.
* Убедиться, что во всех путях TX включается только при подключённой нагрузке и уровень соответствует ожиданию.

### 5.6. Ограничения и защитные блокировки (must-pass)

* **AM:** при выборе мощности ≥ «TUNE KEEP CURRENT» уровень принудительно ограничивается **2W** (`radio_management.c:184-197`): в AM выставить FULL → PWR-бокс/факт = 2W. Зафиксировать.
* **TX вне любительских бэндов:** `Configuration Menu` → `TX on Out-Of-Band Freq.` = OFF (default). Встать на частоту вне бэндов (например, бэнд `Gen` и 27,000 МГц), нажать PTT/Tune → **передача не включается** (радио остаётся в RX; `RadioManagement_ValidateFrequencyForTX`, `radio_management.c:471-483`). Не включать этот пункт без необходимости; если включали — только в эквивалент и на минимальной мощности, затем вернуть OFF.
* **Transmit Disable:** `Configuration Menu` → `Transmit Disable` = ON → PTT/Tune не передают (в CW слышен только sidetone). Вернуть OFF.
* **Смена бэнда/фильтра во время TX** блокируется (UI и CAT); проверка CAT — §7, вручную — нажать BAND+/− во время передачи: бэнд не меняется, реле LPF не щёлкают под мощностью.

### 5.7. Качество тракта 12 кГц / 96 кГц (nice-to-have)

* SSB-сигнал на слух (второй приёмник/монитор SDR): чистый, без «цифрового» дребезга, без лишних комбинаций; CW — без «хвостов»/кликов.
* Двухтоновый Tune (`PA Configuration` → `Tune Tone (SSB)` = `Two Tone`, не сохраняется): контроль на мониторе — два тона, без явных продуктов интермодуляции высокого порядка (качественная оценка).
* Проверить отсутствие «зависаний» звука при переключении TX/RX 20 раз подряд.

### 5.8. Индикация мощности/КСВ на 50 Ом (must-pass, подготовка к §6)

* `PA Configuration` → `Pwr. Display mW` = ON — в TX показываются FWD/REV в мВт (калибровка).
* На 50 Ом при 2 Вт: внутренний SWR-индикатор (нижний, `F2` длинно → SWR) показывает ~1,0–1,2; FWD ≈ мощности; REV ≈ 0.
* При необходимости выполнить калибровки: `Pwr. Det. Null`, `<band> Coupling Adj.`, `SWR/PWR Meter FWD/REV Swap` (если FWD/REV перепутаны — индикации не будет). Записать результат.
* **Без этой проверки результаты §6 недостоверны.**

### 5.9. Нагрев PA (nice-to-have, с ограничением времени)

* 5 Вт в эквивалент, SSB/CW, суммарно 20–30 с; измерить температуру радиатора/корпуса (ИК-пирометр) до/после; сделать паузу.
* Ожидание: нагрев заметный, но без запаха/дыма/термоотказа/зависания; после паузы — штатная работа. При перегреве — прекратить и записать.

## 6. VSWR-защита PA — главный блок (VSWR)

Это основной блок приёмки этапа A (v1.1 P1-1…P1-3 + v1.2 A1). Сначала прочитать §0.4 и §5.8 (индикация на 50 Ом должна быть проверена), затем выполнять сценарии по возрастанию риска. Устройство защиты, калибровка датчика КСВ и матрица нагрузок подробно — в [docs/VSWR.md](VSWR.md) §2/§5/§6 (здесь — приёмочные шаги и критерии).

### 6.1. Как защита устроена (по коду — что и почему ожидаем)

* Порог: меню `Configuration Menu` → `VSWR Protection`: **1 = OFF**, **2..10** — порог в единицах КСВ, default **3**; хранится в EEPROM (слот 426) (`ui_menu_structure.c:123`, `ui_menu.c:2625-2639`, `ui_configuration.c:359`, `radio_management.h:215-218`).
* Измерение: раз в 10 мс в TX (`ui_driver.c:7742-7761`); полное измерение — 5 пар выборок АЦП (`SWR_SAMPLES_CNT = 5`, `radio_management.c:55`), т.е. первое решение физически возможно примерно через **60 мс** после начала передачи (`radio_management.c:78-85`). Валидность — только при прямой мощности ≥ **0,25 Вт** (`SWR_MIN_CALC_POWER`, `ui_driver.h:142`, `radio_management.c:1943`); при больших КСВ значение ограничено 49 (`VSWR_MAX_CALC_VALUE`, `radio_management.c:76`).
* Срабатывание (trip): при сглаженном КСВ выше порога — **PA bias выключается** (`RadioManagement_DisablePaBias()`) и **драйв принудительно минимальный** (0,5 Вт, `PA_LEVEL_MINIMAL = PA_LEVEL_0_5W`), в боксе мощности мигает **`SWR!`** (~3 Гц, на синем фоне) (`radio_management.c:1964-1973`, `ui_driver.c:4828-4866`).
* Пока foldback активен, на **каждом** измерении повторно выставляются bias OFF + минимальный драйв; смена мощности пользователем не возвращает полный драйв (**A1**, `radio_management.c:1978-1980`, `1326-1330`). Запрошенный уровень `ts.power_level` сохраняется.
* Восстановление (release): раз в **8 измерений** (~0,5 с) — recovery-проба: bias включается, но драйв **остаётся минимальным**; при плохом/невалидном измерении — снова mute. После **10 подряд** хороших измерений ниже `порог − 0,5` — release: bias и пользовательский уровень мощности восстанавливаются (`VSWR_PROTECTION_RETRY_CNT=8`, `RECOVERY_CNT=10`, гистерезис 0,5; `radio_management.c:77-85, 1982-2035`). Итого после улучшения нагрузки ожидается восстановление примерно за **0,5–1,2 с** (до ~1,1 с).
* Зона гистерезиса `[порог − 0,5; порог]`: проба **завершается mute PA** (не оставляет bias включённым на минимальном драйве) — это A1-фикс F6; в зоне гистерезиса допустимы короткие периодические пробы (~60 мс с bias ON) примерно каждые ~0,5 с — штатное поведение, но нужно оценить нагрев/ЭМС (`radio_management.c:2029-2035`; см. также A1-R2 в `_audit/dev/p-verify3.md`).
* OFF (порог 1): защита не армится; если была активна — немедленно отпускает PA (`radio_management.c:1927-1934`).
* Порог можно менять на ходу — защита корректна (P3-замечание A1-R4: пункт `PA Bias` в меню может кратко вернуть bias на 1 измерение, драйв при этом минимальный; это безопасно).
* Известный остаточный риск **F1** (не закрыт A1): возможны ложные trip на фронте TX/после Dynamic Tune — проверяется в VSWR-01; это важный полевой тест.

### 6.2. Нагрузки для сценариев (собрать и измерить омметром/КСВ-метром)

| Обозн. | Как собрать | Сопротивление | КСВ (теория) | Замечание |
|---|---|---|---|---|
| L50 | эквивалент 50 Ом | 50 Ом | 1,0 | эталон; ≥5 Вт (лучше 10 Вт) |
| L100 | два эквивалента 50 Ом **последовательно** | 100 Ом | 2,0 | малые мощности; каждый 50-Ом эквивалент ≥5 Вт |
| L25 | два эквивалента 50 Ом **параллельно** | 25 Ом | 2,0 | альтернатива L100 |
| L150 | три эквивалента 50 Ом последовательно | 150 Ом | 3,0 | для уверенного trip при пороге 2 |
| OPEN | антенный разъём без нагрузки (холостой ход) | ∞ | >10 | **только 0,5–1 Вт, коротко** |
| SHORT | разъём с перемычкой центр-оплётка | 0 Ом | >10 | **только 0,5 Вт, ≤1–2 с** |

**Обязательно:** перед сценариями измерить **фактический** КСВ каждой нагрузки внешним КСВ-метром (или по FWD/REV в `Pwr. Display mW`) и записать — защита работает по внутренней калибровке, а не по «теории».

**Ограничения мощности/времени для рассогласованных сценариев:** 0,5–2 Вт, одна передача ≤2–3 с, пауза между попытками. OPEN/SHORT — 0,5–1 Вт, ≤2 с. При пороге 1 (OFF) **не передавать** в OPEN/SHORT (нет защиты): проверку OFF делать только на L100 при ≤2 Вт и коротко.

**Для проверки восстановления «на ходу»** используйте коаксиальный переключатель: TX в L100 → trip → переключить на L50 **не трогая разъёмы под напряжением** (на минимальном драйве это безопасно, но лучше переключатель) → наблюдать release.

### 6.3. Сценарии VSWR

| ID | Условия | Ожидание | Статус |
|---|---|---|---|
| VSWR-01 | L50, порог 3, TX 2 Вт, SSB: 20 передач (в т.ч. первый «dit» в CW, после Dynamic Tune и смены бэнда) | **Нет** ложных `SWR!`/foldback; мощность стабильна (остаточный F1 — если сработало, зафиксировать условия) | must-pass |

| VSWR-03 | L150 (КСВ≈3), порог **2**, 2 Вт, 2–3 с | Trip: `SWR!` мигает, мощность падает до минимальной (~0,5 Вт), PA bias off; время реакции ≈60–150 мс | must-pass |
| VSWR-04 | OPEN, порог 3, 1 Вт (≤2 с) | Trip как VSWR-03; `SWR!` есть | must-pass |
| VSWR-05 | SHORT, порог 3, 0,5 Вт (≤1–2 с) | Trip как VSWR-03; `SWR!` есть; без бурста полной мощности | must-pass |
| VSWR-06 | **A1, ключевой:** после trip (L150/порог 2 или OPEN): не прекращая TX, вращать энкодер PWR-adj (в TX это 3-й энкодер в режиме RIT, индикатор `PWR`, значение 1..110; `ui_driver.c:4053-4087`) до максимума и/или нажимать `G3` (смена уровня) | Мощность в нагрузке **не растёт** (остаётся минимальной), пока foldback активен; экран может мигать `SWR!`/уровнем; полного драйва нет | must-pass |
| VSWR-07 | **Восстановление:** после trip (VSWR-03/04) переключить нагрузку L50 → не прекращая TX, засечь время до восстановления пользовательской мощности (внешний ваттметр + видео) | Восстановление ≈0,5–1,2 с (~1,1 с норма); после — мощность равна пользовательскому уровню, `SWR!` пропал | must-pass |
| VSWR-08 | **Восстановление уровня:** до TX выставить 2 Вт; во время foldback сменить уровень на FULL (`G3`); после VSWR-07 вернуть L50 и дождаться release | После release мощность = **FULL** (последний запрошенный пользователем уровень), т.е. `ts.power_level` сохранён/восстановлен | must-pass |
| VSWR-09 | **Гистерезис/зона (F6):** порог **2**, 2 Вт: войти в foldback на L150 (КСВ≈3), затем переключить нагрузку на L100 (КСВ≈2 — попадает в зону `[1,5; 2]`) на 5–10 с | Пробы в зоне завершаются **mute PA** (bias не «залипает» включённым на минимальном драйве); release нет, полной мощности нет; допустимы короткие периодические всплески минимальной мощности (~60 мс раз в ~0,5 с); нагрев умеренный. Затем переключить на L50 → release | must-pass |
| VSWR-10 | **OFF:** порог **1**, L100, 2 Вт, 1–2 с | `SWR!` нет, мощность не снижается (защита выключена). Затем вернуть порог 3 | must-pass |
| VSWR-11 | **OFF при активном foldback:** на L150/порог 2 войти в foldback, затем установить порог 1 | Немедленный release: PA bias/мощность возвращаются (полная мощность в рассогласование — только на 2 Вт и коротко); после — вернуть порог | nice-to-have |
| VSWR-12 | **Смена порога в foldback:** на L150/порог 2 войти в foldback, поднять порог до 5 | Проба завершится release (КСВ 3 < 5−0,5) — мощность вернётся; поведение безопасно | nice-to-have |
| VSWR-13 | **Персистентность порога:** выставить 5, штатно выключить/включить (длинное PWR) | После включения в меню снова 5 (EEPROM слот 426); вернуть 3 | nice-to-have |
| VSWR-14 | **Tune и защита:** на L150/порог 2 нажать F5 (`TUNE`) | Tune-несущая уходит в foldback (мощность минимальна, `SWR!`), без полного драйва; выход из Tune — возврат в RX | nice-to-have |

**Как измерять тайминги:** видео смартфона в замедленной съёмке 120–240 к/с, в кадре — экран трансивера и стрелка/дисплей внешнего ваттметра; 240 к/с → ~4,2 мс/кадр. Фиксировать: от начала RF до первого снижения мощности; от переключения на L50 до восстановления. Допуск приёмки: trip **≤150 мс** (ожидаемо ~60–80 мс), при этом **отсутствие** бурста полной мощности длиннее ~100 мс; восстановление **0,5–1,5 с**.

### 6.4. Что фиксировать в отчёте по каждому сценарию

Нагрузка и её фактический КСВ, порог, уровень мощности, длительность TX, поведение `SWR!` (есть/нет, мигание), показания внешнего ваттметра до/во время/после, время реакции/восстановления (по видео), поведение PA bias (косвенно — по мощности), температура/нагрев, любые щелчки/зависания. Для VSWR-06/07/08 — отдельно указать, что мощность при вращении PWR-энкодера **не выросла**, и что после release вернулся именно запрошенный уровень.

## 7. CAT/Hamlib и USB-аудио 96 кГц (блоки CAT, USB)

### 7.1. CAT (FT-817 эмуляция, Hamlib ≥4.3)

Интерфейс — виртуальный COM-порт в составе композитного USB-устройства (`cat_driver.c`; FT-817 команды: `SET_FREQ 0x01, GET_FREQ 0x03, PTT 0x08/0x88, MODE 0x07, READ_TX_STATE 0xbd, EEPROM 0xbb/0xbc, 0xf7` и др., `cat_driver.c:717-732`). Поддержка `get_vfo` для Hamlib 4.3 уже в базе Nizar; в v1.1 добавлена эмуляция `0x65` для WSJT-X (P1-5). Смена бэнда/фильтра во время TX блокируется (`CatDriver_IsChangeBandModeAllowed()`, `cat_driver.c:60-63`), ответ — ACK.

**Подключение:**

1. Трансивер выключен → USB-кабель к ПК → включить. В Windows: `Диспетчер устройств` → `Порты (COM и LPT)` → `USB Serial Device (COMx)` (возможен вариант с VID/PID Nizar: производитель `UHSDR Community`; ярлык устройства — ` USB mchf 96KHz `); также появится аудиоустройство. В Linux: `/dev/ttyACM0`, `dmesg | tail`.
2. Если COM-порта нет: установить драйвер USB CDC (Windows 10/11 обычно ставит автоматически); проверить кабель/порт. Зафиксировать фактический COM-порт.
3. Hamlib/WSJT-X: Rig = **FT-817** (FT-817ND); Serial Port = COMx; Baud = 38400 (для USB CDC скорость не критична, но многие программы требуют значение); PTT = CAT (или RTS — только если включён пункт `PTT via virtual RTS`); Data bits 8, stop 1, no parity.
4. `rigctl -l | findstr /i "FT-817"` → числовой ID модели для CLI; проверить: `rigctl -m <ID> -r COMx -s 38400 f`.

|---|---|---|---|

| CAT-02 | get_vfo: `rigctl f`; покрутить VFO на трансивере; повторить | частота читается и **меняется** вслед за VFO (Hamlib 4.3 get_vfo) | must-pass |

## 8. Регрессия и устойчивость (блок REG)

### 8.1. Управление и UI

* **F1** коротко — меню/EXIT; длинно — сохранить настройки в EEPROM.
* **F2** коротко — `sc.snap`/снап (в CW — подстройка по сигналу); длинно — переключение нижнего индикатора (`SWR → ALC → AUD`).
* **F3** коротко — SPLIT (в VFO)/просмотр (в MEM); длинно — переключение VFO/MEM (`vfo_mem_flag`).
* **F4** коротко — VFO A/B; длинно — копирование VFO A→B/B→A.
* **F5** коротко — TUNE; длинно — TX Disable.
* **G1** — режим; **G2** — DSP; **G3** — уровень мощности; **G4** — фильтр (коротко)/альтернатива (длинно).
* **M1/M2/M3** — режимы энкодеров; **PWR** коротко — яркость, длинно — выключение (с сохранением); **BAND+/−**, **STEP+/−** — бэнд/шаг.
* Тачскрин: кнопки F/G/M, перестройка по спектру, zoom (проверить в `Display Menu` и на главном экране).
* Энкодеры: 1/2/3 — проверить в RX и TX (в TX 3-й энкодер в режиме RIT = PWR adj, индикатор `PWR`), без «проскоков»/люфтов, меню: ENC2 — выбор, ENC3 — значение.

### 8.2. VFO/SPLIT и «память»

* VFO A/B: F4 коротко — переключение без потери частоты; F4 длинно — копирование частоты/режима в другой VFO (сообщение `VFO A -> VFO B`/`VFO B -> VFO A`, `ui_driver.c:1262-1287`).
* SPLIT: F3 коротко в VFO-режиме — вкл/выкл SPLIT (`UiDriver_SetSplitMode`), отображение частот RX/TX; выйти из SPLIT.
* **Каналы памяти:** в этой UI-сборке нет функций store/recall каналов (метка памяти закомментирована, `ui_driver.c:1784-1797`; `mem_disp` лишь скрывает спектр). Не требовать сохранения ячеек памяти; отметить как известное ограничение (NA), не FAIL. Перед тестом уточните в отчёте, что «MEM»-режим ограничен.

### 8.3. Питание, выключение, повторные включения

* 5 циклов «выключить (длинное PWR, с сохранением) → включить»: каждый раз старт без зависаний, настройки сохраняются.
* Выключение без сохранения (BAND+ + длинное PWR) — см. RX-12.
* Загрузка дефолтов (если нужно для чистого теста): при включении удерживать **F1+F3+F5** — появляется экран `ALL DEFAULTS` / `-> LOAD REQUEST <-` с предупреждением `If you want to load default settings press and hold BAND+ AND BAND-`; подтверждение — удержать **BAND+ и BAND−** (настройки сохранятся при выключении питания), **PWR** — нормальный старт без изменений (`ui_driver.c:5476-5580`). **Осторожно:** это сбрасывает настройки (после — восстановить бэкап/вручную).
* Проверка индикации напряжения/питания: на главном экране вольтметр (если включён) и предупреждения по низкому напряжению — без ложных срабатываний (nice-to-have).

### 8.4. Watchdog и зависания (важно понимать ограничение)

По коду **аппаратный watchdog в этой сборке не включён**: `HAL_IWDG_MODULE_ENABLED`/WWDG закомментированы (`basesw/mcHF/Inc/stm32f4xx_hal_conf.h:69,81`), вызов инициализации закомментирован (`hardware/uhsdr_board.c:398-399` «Init watchdog - not working»). Поэтому:

* Тест «watchdog перезагрузит при зависании» **неприменим** — при зависании устройство не перезапустится само.
* Критерий — **отсутствие зависаний** при длительной работе (§8.5). При зависании: зафиксировать условия, снять питание, повторить сценарий; зависание **в TX** — `FAIL` (см. §9.3).

### 8.5. Длительный прогон (soak)

* 60 минут смешанной работы: приём со спектром/водопадом, периодические TX (0,5–2 Вт в эквивалент, 5–10 с), смена бэндов/режимов/фильтров, опрос CAT (WSJT-X в RX), USB-аудио запись.
* Наблюдать: зависания, самопроизвольные перезагрузки, пропадание звука/панорамы, отвалы CAT/USB, рост температуры PA, ложные `SWR!` на 50 Ом.
* После прогона — повторить VSWR-01 (20 передач на 50 Ом) — контроль отсутствия ложных срабатываний после «прогрева».

### 9.3. Условия немедленного FAIL (независимо от остальных результатов)

1. Любое **непреднамеренное излучение полной мощности в рассогласованную нагрузку** (OPEN/SHORT/КСВ выше порога) при активной защите.
2. Отсутствие `SWR!`/foldback там, где по §6 он обязан сработать (VSWR-03/04/05).
3. **A1 не работает**: при активном foldback смена мощности (PWR-энкодер/G3) поднимает выходную мощность (VSWR-06).
4. Зависание/перезагрузка **во время передачи** или требование передёрнуть питание для выхода из TX.
5. Передача при отсутствии нагрузки/при отказе индикации (в т.ч. TX-10 не блокирует TX вне бэндов).
6. Потеря/порча настроек EEPROM после штатного выключения (RX-11) или «кирпич» после прошивки/отката.

### 9.4. Формула вердикта

* **PASS** — все must-pass PASS; нет условий §9.3; nice-to-have записаны.
* **CONDITIONAL PASS** — все must-pass PASS, но есть FAIL/PARTIAL в nice-to-have и/или задокументированные отклонения (например, загрузчик 4.1.2 вместо 5.0.4) — допускается к полевым испытаниям с оговорками.
* **FAIL** — хотя бы один must-pass FAIL или любое условие §9.3.

**10.3.2. Загрузчик: 5.0.4 → 4.1.2 known-good (только при проблемах; риск «кирпича»).**

* Только DFU/SWD (§3.3): `STM32_Programmer_CLI.exe -c port=USB1 -w bl-mchf-4.1.2-known-good.bin 0x08000000 -v -rst`.
* **Не включать полное стирание чипа** (full chip erase): будут стёрты секторы эмуляции конфигурации 0x08008000..0x0800FFFF (бэкап настроек) и, возможно, данные; при стирании чипа — заново `Restore Config`/дефолты.
* После перезагрузки: System Info → `Bootloader = 4.1.2` (строка `Version: 4.1.2`), прошивка стартует; загрузчик 4.1.2 совместим с прошивкой 2.9.48 (см. docs/PATCHES.md P2-1, docs/BOOTLOADER.md).
* Перед операцией обязательно снять полный дамп 1 МиБ (§2.4, вариант 2), если доступен SWD.

**10.3.3. «Кирпич»/не стартует.**

1. ROM-DFU: BAND+ при включении (§3.3) → прошить `fw-mchf.hex`/`bl-mchf-5.0.4.hex`; при необходимости — загрузчик 4.1.2.
2. Если DFU недоступен — метод P6-джампера/программатора (см. `mchf-eclipse/useful_manuals/bootloader_install.pdf`, upstream `bootloader_doc.md`); подробности — [docs/BOOTLOADER.md](BOOTLOADER.md).
3. Не разбирать трансивер под напряжением; при сомнениях — остановиться и зафиксировать.

**10.3.4. Сброс настроек к дефолтам** (если после отката/обновления настройки неадекватны): при включении удерживать **F1+F3+F5** → экран `ALL DEFAULTS` / `-> LOAD REQUEST <-`; подтвердить, удерживая **BAND+ и BAND−** (настройки сохранятся при выключении), либо **PWR** — обычный старт (`ui_driver.c:5476-5580`). После сброса — заново выставить: `VSWR Protection = 3`, калибровки КСВ (FWD/REV), PA bias/уровни, фильтры; сверить с бэкапом значений (§2.2).

**10.3.5. Возврат на v1.2** после отката — тем же способом (A/B), проверить ID-01…ID-03 и повторить короткий smoke (RX-04/05, TX-01, VSWR-02).

## Приложение C. Известные ограничения и риски, влияющие на вердикт

1. **FreeDV в сборке не включён** (`IS_SMALL_BUILD`, `USE_FREEDV` не определён; в прошивке нет FreeDV-функций). Не проверять и не считать дефектом; A2-гейты — «на будущее» (docs/PATCHES.md, P2-2/A2).
2. **Аппаратный watchdog не включён** (`hardware/uhsdr_board.c:398-399`, `stm32f4xx_hal_conf.h:69`): при зависании нет авто-перезагрузки; критерий — отсутствие зависаний.
3. **Числовой dBm-индикатор выключен** принудительно (NIZZZ, `ui_configuration.c:189`); S-метр — в S-единицах.
4. **Каналы памяти** в этом UI не реализованы (только per-band VFO); тест памяти — NA/ограничение.
5. **Загрузчик 5.0.4 на железе не испытывался** (собран/линкован): обновлять только при необходимости/DFU/SWD, с бэкапом; 4.1.2 совместим и есть как known-good.
6. **Остаточный риск F1**: ложные trip по КСВ на фронте TX/после Dynamic Tune не закрыты A1 — проверять VSWR-01 и фиксировать условия.
7. **Периодические пробы в зоне гистерезиса** (A1 F6/R2): ~60 мс с bias ON примерно раз в ~0,5 с — штатно; следить за нагревом/ЭМС.
8. **Пункт меню `PA Bias`** может кратко (≤1 измерения) вернуть bias при foldback (A1-R4) — драйв при этом минимальный, безопасно.
9. **CAT FT-817**: SET-команды мощности в этой прошивке нет; внутрибэндовый `SET_FREQ` в TX может применяться (WSJT-X Fake It), смена бэнда/фильтра — нет (P0-5/P1-5).
10. **Расхождения в docs**: docs/BUILD.md §5.1 (USB-диск на ПК) и формулировка «автообновление» в RELEASE-NOTES — см. §0.3; тестировать по коду (загрузчик — USB-хост, нужен BAND−).
11. **Сборка не побайтово воспроизводима** (`fwt-…`); для релизного артефакта Build фиксирован (`Nov 26 2026 - 23:58:46`), для своей пересборки — записать фактическую строку.
12. **CCM заполнена на 96,9 %** — не прошивать сборки с новыми CCM-буферами без пересчёта карты; использовать только проверенные артефакты.
